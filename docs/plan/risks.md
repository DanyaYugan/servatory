# Риски и меры

## Технические

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Docker API различается между версиями | средняя | среднее | минимальный набор вызовов, тесты на 24+/26+, `docker version` в диагностике |
| Относительные пути compose ломаются в контейнере | высокая | высокое | монтировать проект по тому же абсолютному пути; документировать; проверка при старте |
| Caddy принимает конфиг, но сайты не работают | средняя | высокое | validate → load → проверка домена → last_good → откат |
| Потеря данных при удалении сервиса | средняя | критическое | том по умолчанию сохраняется; подтверждение с вводом имени; audit |
| Бэкап тома «пустой» из-за прав | средняя | высокое | проверка `tar -tzf`, размер > 0, статус failed иначе |
| Самообновление hub ломает операцию | высокая | среднее | hub не обновляет сам себя; отдельный юнит/контейнер и CLI |
| Два экземпляра бота (409) | средняя | низкое | блокировка на файл/лок в /data |
| SQLite и параллельные записи | средняя | среднее | WAL, одна очередь записи, короткие транзакции |
| Секреты попадают в логи | средняя | высокое | маскирование в логгере, тест на отсутствие значений |
| Socket-proxy не покрывает нужный вызов | средняя | среднее | белый список проверить на всех действиях заранее |

## Продуктовые

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Слишком широкий охват 1.0 | высокая | высокое | чёткое MVP, вынос Caddy/обновлений при отставании |
| Мало пользователей из-за сложной установки | средняя | высокое | мастер, демо, quickstart, одна команда |
| Нет доверия к панели с доступом к Docker | средняя | высокое | открытый код, socket-proxy, аудит, минимум прав |
| Конкуренция с Portainer/CasaOS | средняя | среднее | фокус: Telegram, метки, роли, переносимость |
| Лицензионные претензии | низкая | среднее | Apache 2.0, без GPL-зависимостей, NOTICE |

## Организационные

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Долгие паузы между сессиями | высокая | среднее | handoff-заметки, чек-листы, самодостаточная папка |
| Работа «по памяти» без спеки | средняя | высокое | сначала документ, потом код |
| Тестирование только на живом стенде | высокая | высокое | интеграционные тесты с testcontainers до ручных проверок |
| Расширение объёма «по ходу» | высокая | высокое | новые идеи — в backlog, не в текущий этап |

## Откат по этапам

| Этап | Как откатить |
|---|---|
| 1 | удалить данные hub, контейнер не трогает сервисы |
| 2 | вернуть прошлый образ/тег hub |
| 3 | восстановить базу из pre-migrate копии |
| 4 | вернуть last_good конфиг Caddy |
| 5 | выключить бота флагом |
| 6 | остановить jobs |
| 7 | вернуть прошлый тег |

## Решения, которые нельзя откладывать

```
формат пути данных (/data)              иначе миграции болезненные
версия схемы с самого начала            иначе обновления ломают установки
разделение core и jobs                  иначе слепота при падении
отсутствие GPL-зависимостей             иначе лицензионные ограничения
```
