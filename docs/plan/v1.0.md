# Servatory 1.0 — план

Название продукта: **Servatory**. Логотип и стиль — `../brand/brand.md`.
Версионирование — `versioning.md`: три числа, стадии alpha/beta/rc.
Целевой релиз этой версии — **1.0.0**, до него идут `0.x.y-alpha` и `0.x.y-beta`.

Это первая версия: только ядро и веб, без бота и приложения.

---

## 1. Задача версии

```
поставить панель на один сервер,
подключить к ней Docker-хосты (этот и другие),
увидеть все контейнеры в одном списке,
устанавливать, обновлять и удалять их из браузера,
раскладывать по группам и менять порядок.
```

## 2. Что входит

```
ядро + веб в одном процессе
вход: один администратор, пароль, сессия
несколько Docker-хостов: локальный сокет и удалённый по TLS
главная: все сервисы со всех хостов, группы, порядок
карточка сервиса: образ, порты, тома, статус, действия
установка контейнера: образ, имя, порты, тома, переменные
удаление: с вопросом про том
запуск, остановка, перезапуск
обновление с откатом образа
бэкапы: создание, список, хранение (без восстановления)
состояние: контейнер работает или нет
журнал операций (кто и что делал, результат)
данные в /data, перенос копированием каталога
```

## 3. Чего в 1.0 нет

```
бот и уведомления
роли и права пользователей
домены и TLS через панель
восстановление из бэкапа
дампы баз
метрики: CPU, память, диск, графики, Prometheus
логи в браузере
живое обновление экрана (SSE)
перетаскивание мышью
английский язык
страница настроек
HTTP-проверки сервисов
стеки compose
Proxmox
агент для удалённых хостов
```

## 4. Архитектура

```
один процесс: core + web
FastAPI + SQLite (WAL) + Alembic
Vue 3 + Vite, статика отдаётся тем же процессом
провайдеры: docker-local (unix socket), docker-remote (TLS)
```

Провайдер — единственное место, которое знает, как говорить с Docker.
Ядро работает с абстракцией «контейнер на хосте».


## 11. Риски

```
TLS к удалённому Docker   нужны сертификаты и открытый порт 2376
обновление без восстановления  откат вернёт образ, но не данные
один администратор        компромисс ради сроков
Compose не пересоздаёт при смене digest  нужен --force-recreate
```

## 12. Версионирование

Полные правила — `versioning.md`. Коротко для этой версии:

```
формат         MAJOR.MINOR.PATCH, например 1.0.0
до 1.0.0       0.1.0-alpha.1 → 0.4.0-beta.1 → 0.9.0-rc.1 → 1.0.0
alpha          внутренние сборки, функции и схема могут меняться
beta           публичное тестирование, функции заморожены
rc             только критичные исправления
1.0.0          стабильный релиз
```

Где фиксируется:

```
git tag v1.0.0
app/version.py: __version__
GET /api/v1/meta → {"version": "1.0.0", "schema": N}
Docker: ghcr.io/servatory/servatory:1.0.0, :1.0, :latest
CHANGELOG.md
```

Версия продукта и версия схемы БД — разные числа: схема может увеличиться
на патче, если понадобилась миграция.
