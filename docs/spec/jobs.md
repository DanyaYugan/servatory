# Jobs: алерты и расписание

Отдельный процесс. Читает базу только на чтение, проверки выполняет сам,
уведомления отправляет напрямую в Telegram. Работает, даже если `hub` упал.

## Что делает

```
проверки здоровья       http, tcp, container
возраст бэкапов         последняя копия старше N дней
диск                    свободно меньше N%
обновления              появилось новое обновление
ошибки операций         failed за последние N минут
watchdog                hub не отвечает, jobs не отчитывался
сводка                  утренний дайджест
```

## Правила

```json
{
  "kind": "health",
  "config": {"service_ids": ["..."], "fails_before_alert": 2},
  "severity": "warning",
  "targets": {"telegram": ["123456789"]},
  "enabled": true
}
```

Типы `kind`: `health`, `backup_age`, `disk`, `updates`, `operation_failed`,
`watchdog`, `digest`.

## Расписание

```
проверки здоровья    каждые 60 с (интервал из checks)
обновления           07:45
сводка               08:00
диск и бэкапы        каждый час
watchdog             каждые 2 минуты
```

Всё настраивается, значения по умолчанию — выше.

## Тишина и дедупликация

```
quiet_hours     с 23:00 до 07:30, предупреждения подавляются,
                критичные проходят
дедупликация    одно и то же событие не чаще раза в 6 часов
эскалация       если проблема держится > 1 часа — повторить
восстановление  сообщение «снова в норме» после устранения
```

Состояние дедупликации хранится в `/data/jobs-state.json`, чтобы переживать
перезапуск.

## Watchdog

```
каждые 2 минуты: GET http://hub:8080/health (таймаут 5 с)
3 провала подряд → сообщение «hub недоступен»
восстановление → сообщение «hub снова отвечает»
jobs пишет heartbeat в /data/jobs-heartbeat каждые 30 с
```

Heartbeat нужен, чтобы отличить «hub упал» от «jobs упал».

## Каналы

```
telegram   Bot API sendMessage; токен из /data/secrets
webhook    POST JSON на указанный URL (1.2)
email      SMTP (1.2)
```

Формат сообщения:

```
🟠 <b>Miniflux</b> не отвечает 3 проверки подряд
https://rss.example.com
последняя ошибка: timeout 5s
время: 22.10 09:14
```

## Запуск

```
docker:  отдельный контейнер jobs в том же образе, команда `hub jobs`
systemd: hub-jobs.service с тем же бинарём
```

Не запускается вместе с `hub` по умолчанию: это осознанное разделение,
чтобы падение одного не глушило другое.

## Ограничения

```
если упал весь хост — уведомлений нет; нужна внешняя проверка
если Telegram недоступен — сообщения копятся в очереди и уходят позже
```
