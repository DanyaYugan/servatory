# Структура интерфейса Servatory

Основа — то, как сейчас выглядит Homepage на основной ВМ: тёмная тема,
карточки с точкой статуса, группы, быстрый переход по ссылке.
Servatory сохраняет эту картину, но добавляет управление сервисами.

## 1. Принцип

```
Homepage   = витрина: посмотреть и перейти
Servatory  = витрина + управление: посмотреть, понять состояние, сделать
```

Два режима в одном интерфейсе:

```
обзор    — все сервисы, статусы, группировка, поиск
сервис   — один сервис: состояние, действия, бэкапы, настройки
```

## 2. Карта экранов

```
/                     Обзор
/services/:name       Страница сервиса
/install              Установка
/settings             Настройки: общие, группы, хосты
/login                Вход
```

## 3. Каркас

Сверху — шапка: логотип, поле виджетов, две кнопки. Ниже — рабочее пространство.

```
┌──────────┬──────────────────────────────────────────┬───────────────┐
│ S Servatory │      поиск сервисов (виджет)          │ ＋     ⚙      │
│            │                                        │ Добавление Настройки │
├──────────┴──────────────────────────────────────────┴───────────────┤
│                                                                     │
│                        рабочее пространство                          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

```
слева    логотип и название
центр    поле виджетов: сейчас поиск, позже время и погода
справа   «Добавление» и «Настройки»
ниже     страницы: обзор, сервис, установка, настройки
```

Группы и хосты живут внутри настроек отдельными вкладками.

## 4. Обзор

```
заголовок группы и число сервисов
сетка карточек, до 4 в ряд
фильтр по группе из сайдбара
поиск по имени и образу
сводка сверху: работает / остановлено / есть обновления
```

Пустое состояние: «Сервисов пока нет» и кнопка «Установить первый».

## 5. Карточка сервиса

Карточка — краткая. Всё подробное — на странице сервиса.
Кнопок на карточке две: «Открыть» и меню «⋯». Остальные действия — в меню.

```
┌──────────────────────────────────────┐
│ ● Miniflux                    RSS    │
│ miniflux/miniflux:2.3.4              │
│ 8080 → 8080/tcp                      │
│ Открыть ↗                      [⋯]   │
└──────────────────────────────────────┘
```

```
точка      зелёная — работает, серая — остановлен
значок    группа или иконка сервиса (иконки позже)
версия    если есть обновление — метка «есть обновление»
ссылка    открывает сервис в новой вкладке
кнопки    только «Открыть» и меню ⋯
клик      по карточке (не по кнопке) — страница сервиса
```

В меню ⋯:

```
Стоп / Запуск
Перезапуск
Обновить
Бэкап
Ссылка
Настройки
Удалить
```

Кнопки не выходят за карточку: перенос строк, меню вместо длинного ряда.

## 6. Страница сервиса

```
┌─────────────────────────────────────────────────────────────┐
│ ← Назад   Miniflux          ● работает     [Открыть ↗]      │
│ miniflux/miniflux:2.3.4 · обновлений нет                    │
├─────────────────────────────────────────────────────────────┤
│ Обзор   Бэкапы   Настройки                                  │
├─────────────────────────────────────────────────────────────┤
│ Состояние     работает, 2 дня                               │
│ Порты         8080 → 8080/tcp                               │
│ Тома          miniflux-data:/var/lib/miniflux               │
│ Сеть          homelab_web                                   │
│ Группа        Локальные сервисы        [изменить]           │
│ Образ         miniflux/miniflux:2.3.4  [обновить]           │
│ Действия      [Стоп] [Перезапуск]                           │
└─────────────────────────────────────────────────────────────┘
```

Вкладки:

```
Обзор       состояние, порты, тома, группа, ссылка, действия
Бэкапы      список копий, создать, восстановить, удалить
Настройки   ссылка, группа, политика обновления, удаление
Логи        позже, отдельным шагом
```

Правило: карточка отвечает «что это и работает ли», страница — «как устроено
и что можно сделать».

## 7. Установка

Один экран, три шага. Не модальное окно поверх карточек.

```
┌─────────────────────────────────────────────────────────────┐
│ Установка                                                   │
│ 1 Образ   2 Параметры   3 Проверка                          │
├─────────────────────────────────────────────────────────────┤
│ ( ) Поиск на Docker Hub     ( ) Вставить YAML               │
│                                                             │
│ [ nginx                              ]  → подсказки         │
│                                                             │
│ Имя        [ web                ]                           │
│ Порты      [ 8085:80/tcp        ]                           │
│ Тома       [ data:/usr/share/nginx/html ]                  │
│ Переменные [ TZ=Asia/Yekaterinburg ]                       │
│ Перезапуск [ unless-stopped     ]                          │
│                                                             │
│                              [Установить]                   │
└─────────────────────────────────────────────────────────────┘
```

После установки — переход на страницу нового сервиса, а не просто баннер.

## 8. Группы

Находятся в «Настройках», вкладка «Группы».

```
групп по умолчанию нет
пока группа не создана, все сервисы в разделе «Без группы»
создать, переименовать, удалить
порядок стрелками
перенос сервиса — из карточки или страницы сервиса
```

Позже: перетаскивание.

## 9. Хосты

Находятся в «Настройках», вкладка «Хосты». Пока один локальный:

```
┌─────────────────────────────────────────────┐
│ Этот сервер                    ● подключён  │
│ Docker 29.1.3 · сокет /var/run/docker.sock  │
│ сервисов: 12                                │
└─────────────────────────────────────────────┘
```

Удалённые хосты — в 0.3.0, кнопка «Добавить хост» появится тогда же.

## 10. Настройки

```
Общие        порт, адрес, язык
Безопасность вход, срок сессии, пароль
Бэкапы       каталог, сколько хранить
Docker       сокет, таймаут
О системе    версия, схема базы, лицензия
```

Пользователи и роли — когда появится RBAC.

## 11. Состояния

Для каждого экрана:

```
загрузка   скелетон или «Загрузка…», без прыжков
пусто      объяснение и действие
ошибка     что случилось и что делать
нет прав   «Недостаточно прав» (когда появятся роли)
```

## 12. Терминология

```
сервис        контейнер, которым управляет панель
группа        пользовательская группировка сервисов
хост          Docker-сервер (пока один — этот)
образ         Docker-образ, версия
том           постоянное хранилище данных
копия         бэкап томов
восстановить  вернуть данные из копии
открыть       перейти на сайт сервиса
```

## 13. Homepage остаётся

Homepage на основной ВМ остаётся основным интерфейсом. Servatory — отдельный
проект на отдельной ВМ, и на этом сервере они не пересекаются.

Правило для этого сервера:

```
Servatory не управляет контейнерами основной ВМ
не добавляет карточки и ссылки на её сервисы
не читает её конфиги и метрики
на тестовой ВМ живут только servatory и тестовые контейнеры
```

Это правило конкретного сервера, а не ограничение продукта. В продукте
внешние сервисы, импорт карточек и несколько хостов остаются возможными —
другим пользователям это нужно.

Из Homepage берём только визуальные находки: тёмную тему, карточки,
точки статуса, плотность. Сам Homepage не трогаем и не выводим из работы.

Внешние сервисы без Docker остаются функцией продукта: они пригодятся,
когда на тестовой ВМ появятся службы вне Docker или когда Servatory
поставят на сервер, где есть нативные сервисы.

## 15. Решения

```
верхняя панель           да: лого, поиск, добавление, настройки
страница сервиса         подробная, отдельная
на карточке              только «Открыть» и меню ⋯
группы по умолчанию      не создавать, только «Без группы»
Homepage                 остаётся; Servatory отдельно и не пересекается
```
