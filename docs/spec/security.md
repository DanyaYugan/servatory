# Безопасность

## Модель угроз (кратко)

| Угроза | Последствие | Мера |
|---|---|---|
| кража сессии | полный доступ к панели | httpOnly, Secure, SameSite, отзыв сессий |
| подбор пароля | вход | argon2id, лимит попыток, блокировка, TOTP |
| утечка API-токена | доступ в рамках scopes | хеш, срок, scopes, отзыв |
| доступ к docker.sock | root на хосте | socket-proxy, только core, минимум прав |
| подмена Caddy-конфига | перенаправление трафика | validate, last_good, audit |
| подделка вебхуков | ложные действия | подпись, секрет |
| утечка секретов | доступ к сервисам | шифрование, права 600, не логировать |
| компрометация агента | управление хостом | mTLS, одноразовый токен, отзыв |

## Docker

```
hub (в контейнере) не получает /var/run/docker.sock напрямую по умолчанию
вместо этого — socket-proxy с белым списком:
  CONTAINERS=1, IMAGES=1, NETWORKS=1, VOLUMES=1, EXEC=0, POST=1
  (EXEC отключён: бэкап делается через --volumes-from, а не exec в чужих контейнерах)
нативный режим: пользователь hub в группе docker
```

## Секреты

```
хранение   AES-GCM, ключ /data/key (32 байта, 600, генерируется при установке)
в базе     только шифротекст, nonce рядом
использование  подстановка при генерации compose: ${secret:NAME}
логи       значения маскируются: ****
экспорт    опционально, зашифрованным архивом с паролем
```

## Веб

```
CSRF          заголовок X-CSRF-Token для изменяющих запросов
CORS          запрещён по умолчанию; только same-origin
заголовки     CSP, X-Frame-Options: DENY, Referrer-Policy: no-referrer
upload        не принимается (кроме импорта JSON с проверкой размера)
rate limit    /auth/login 10/мин на IP, API 300/мин на токен
```

## API

```
Bearer-токены, scopes — подмножество прав пользователя
каждый запрос пишется в audit при изменяющих операциях
Idempotency-Key обязателен для действий с деньгами/данными (у нас — все POST-действия)
```

## Агент (1.1)

```
транспорт   WebSocket наружу с хоста к hub (не требует входящих портов)
аутентификация  mTLS или одноразовый токен регистрации (TTL 15 минут)
права       только операции из белого списка: list, inspect, pull, create, remove
обновление  агент сам сообщает версию; hub предупреждает о расхождении
```

## Секреты в репозитории

```
.gitignore: .env, *.key, /data, *.db, *.log
CI: секреты только через GitServatory Secrets
образы: не содержат ключей; проверять `docker history`
```

## Резервное копирование безопасности

```
копия hub.db и /data/key — отдельно от основных бэкапов
ключ хранить в менеджере паролей (у пользователя)
при потере ключа секреты не восстановить — это ожидаемо, документируется
```

## Что осознанно не делаем в 1.0

```
подпись плагинов         плагинов нет
RBAC на уровне полей     только на действия
аудит чтения             только изменения
WAF                      забота внешнего прокси
```
