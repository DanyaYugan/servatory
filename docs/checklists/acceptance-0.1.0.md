# Проверка Servatory 0.1.0 вместе

Ориентир: 40–60 минут. Отмечай пункты, всё что не совпало — записывай.

## Подготовка

```
панель:   http://<host>:8090/ui/
логин:    admin
пароль:   admin
ВМ:       104 test, <host>
```

Перед началом на главной должно быть два сервиса: `servatory` и `uptime-kuma`.

## A. Вход и выход

- [ ] A1. Открыть панель в приватном окне — появляется форма входа, а не запрос пароля браузера
- [ ] A2. Ввести неверный пароль — сообщение «неверный логин или пароль», панель не пускает
- [ ] A3. Ввести admin/admin — открывается главная
- [ ] A4. Обновить страницу — сессия сохраняется, снова логин не просит
- [ ] A5. В шапке видно `admin · superadmin` и версию `v0.1.0-alpha.11`
- [ ] A6. Нажать «Выйти» — возвращает на форму входа
- [ ] A7. Открыть `/api/v1/containers` в соседней вкладке — 401

## B. Главная и лампы

- [ ] B1. Два сервиса, у обоих зелёные лампы и «работает»
- [ ] B2. Указаны образ, порт, короткий id
- [ ] B3. Нажать «Обновить» — время обновления меняется
- [ ] B4. Остановить `uptime-kuma` кнопкой «Стоп» — лампа серая, подпись «остановлен», кнопки «Старт» и «Удалить»
- [ ] B5. Запустить обратно — зелёная лампа, «работает»

## C. Группы

- [ ] C1. «Группы» → создать «Медиа» — группа появилась в списке
- [ ] C2. Переименовать в «Медиа и кино» — имя изменилось
- [ ] C3. Создать вторую группу «Дом»
- [ ] C4. Стрелками поменять порядок — группы меняются местами
- [ ] C5. На карточке `uptime-kuma` выбрать «Медиа и кино» — сервис переехал в раздел
- [ ] C6. Выбрать «Без группы» — вернулся в общий раздел
- [ ] C7. Удалить группу с сервисом — сервис остался, группа исчезла

## D. Установка и поиск образа

- [ ] D1. «Добавить сервис» → в поле «Образ» ввести `nginx` — через секунду появились подсказки
- [ ] D2. Выбрать `library/nginx` — имя подставилось, появился список тегов
- [ ] D3. Заполнить: имя `demo-web`, порт `8083:80/tcp`, перезапуск `unless-stopped`
- [ ] D4. «Установить» — карточка появилась, `http://<host>:8083` открывается
- [ ] D5. Попробовать установить с тем же именем — ошибка «имя занято»
- [ ] D6. Попробовать имя с пробелом — ошибка про допустимые символы
- [ ] D7. Попробовать порт `abc` — ошибка про формат порта
- [ ] D8. Удалить `demo-web` — карточка исчезла, порт закрылся

## E. Обновление

Для плавающего тега:

- [ ] E1. На ВМ выполнить подготовку (команды ниже), появится `update-demo`
- [ ] E2. Нажать «Обновить» — баннер «обновлён <старый> → <новый>»
- [ ] E3. Порт 8096 отвечает, версия nginx изменилась
- [ ] E4. Нажать «Обновить» ещё раз — «уже последняя версия»

Для закреплённого тега:

- [ ] E5. Установить `pinned-demo` с образом `nginx:1.25-alpine`, порт `8097:80/tcp`
- [ ] E6. «Обновить» — «уже последняя версия», контейнер не пересоздаётся

Подготовка E1:

```bash
sudo docker rm -f update-demo
sudo docker pull -q nginx:1.25-alpine
sudo docker tag nginx:1.25-alpine nginx:alpine
sudo docker run -d --name update-demo -p 8096:80 nginx:alpine
```

## H. Восстановление

- [ ] H1. Записать маркер в том Кумы:

```bash
sudo docker run --rm -v uptime-kuma:/data alpine sh -c 'echo test > /data/marker.txt'
```

- [ ] H2. «Копии» → «Восстановить» → ввести `uptime-kuma`
- [ ] H3. Баннер: восстановлено, safety-копия
- [ ] H4. Маркер исчез:

```bash
sudo docker run --rm -v uptime-kuma:/data alpine test -f /data/marker.txt && echo ЕСТЬ || echo НЕТ
```

- [ ] H5. `http://<host>:3001` открывается, данные на месте
