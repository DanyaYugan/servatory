# Дорожная карта

Этапы разработки с приёмкой. Каждый этап заканчивается проверкой и
возможностью откатиться.

---

## Принцип нарезки

```
сначала чтение, потом запись
сначала свои данные, потом чужие сервисы
сначала один пользователь, потом роли
сначала локальный Docker, потом удалённые хосты
```

---

## Этап 0. Каркас

**Делаем**

```
репозиторий, лицензия Apache 2.0, README
структура backend/, frontend/, deploy/, docs/
CI: ruff, pytest, сборка фронта, образы amd64/arm64
Dockerfile (multi-stage), compose.yml, entrypoint
install.sh для нативного режима
```

**Приёмка**

```
образ собирается и запускается
тесты проходят в CI
docker compose up -d поднимает пустой hub с /health
```

---

## Этап 1. Скелет: чтение

**Делаем**

```
SQLite + Alembic, базовые таблицы
docker-local провайдер: список, inspect, события
GET /api/v1/services, /state, /events
Vue-каркас: список карточек, состояние, SSE
systemd-юнит и запуск в контейнере
```

**Приёмка**

```
видны все контейнеры, включая без меток
метки hub.* превращаются в поля карточки
создал контейнер — появился без перезагрузки
перезапуск hub — состояние на месте
```

---

## Этап 2. Пользователи и права

**Делаем**

```
users, roles, permissions, grants
сессии, CSRF, argon2, TOTP (опционально)
api_tokens со scopes
аудит входов и изменений
страницы /users, /roles, /audit
```

**Приёмка**

```
вход, выход, блокировка после N попыток
viewer не может менять, operator может, admin всё
токен с ограниченными scopes не делает лишнего
всё в журнале
```

---

## Этап 3. Действия

**Делаем**

```
add / remove / update / backup / restore
операции с operation_id и статусом
блокировка на сервис, идемпотентность
бэкап тома через --volumes-from
откат на прежний образ и конфиг
```

**Приёмка**

```
тестовый контейнер: добавлен, обновлён, удалён
при сбое обновления вернулся прежний образ
удаление с сохранением тома работает
повторное добавление не создаёт дубль
```

---

## Этап 4. Вход и Caddy

**Делаем**

```
режимы managed / external / labels / none
генерация JSON-конфига, validate, load с etag
last_good и откат
маршрут из карточки сервиса
```

**Приёмка**

```
сервис получает домен и сертификат из UI
ошибка в конфиге не роняет сайты, откат срабатывает
external-режим правит чужой Caddy
```

---

## Этап 5. Бот

**Делаем**

```
long polling, привязка telegram_id → user
команды: статус, список, обновления, логи, обновить
inline-подтверждения
```

**Приёмка**

```
команды уважают права пользователя
обновление из бота делает бэкап и откат
второй экземпляр бота не запускается
```

---

## Этап 6. Jobs

**Делаем**

```
отдельный процесс, чтение базы только на чтение
правила: health, backup_age, disk, updates
quiet hours, дедупликация, эскалация
уведомления в Telegram напрямую
watchdog для hub и jobs
```

**Приёмка**

```
остановили hub — алерты продолжают приходить
тихие часы работают, критические проходят
дубли не спамят
```

---

## Этап 7. Продукт

**Делаем**

```
мастер первого запуска
поиск и применение обновлений с политикой
миграции схемы и версия в интерфейсе
экспорт/импорт настроек (с шифрованием)
демо-режим
```

**Приёмка**

```
установка с нуля за 5 минут по quickstart
обновление с 1.0 на 1.1 без ручных шагов
экспорт на одной машине, импорт на другой
```
