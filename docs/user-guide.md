# Servatory 0.2.0-beta — что умеет панель

Версия: `0.2.0-beta`. Ниже всё, что доступно пользователю.

## 1. Вход и пользователи

```
адрес:  http://<сервер>:8090/ui/
логин:  admin
пароль: admin
```

Первый администратор создаётся из `config.toml` (`[auth] login`, `password`)
при первом входе. Дальше пользователи живут в базе, пароли хранятся хешем.

Роли:

```
superadmin  всё, включая пользователей
admin       сервисы, действия, бэкапы, группы, ссылки
operator    просмотр и действия: старт, стоп, перезапуск, обновление
viewer      только просмотр
```

Пользователи добавляются в «Настройки → Пользователи» (только superadmin).
Своя учётная запись — в «Настройки → Безопасность»: сменить пароль,
посмотреть роль. Свою роль изменить нельзя, даже superadmin.
Сессия живёт 12 часов (`session_hours`), хранится в cookie HttpOnly.
Выход — «Настройки → Общие».

Если войти не удалось — панель покажет причину: неверный логин или пароль.

## 2. Навигация и главная

Слева — разделы панели:

```
Обзор
Установить
Группы
Хосты
Настройки
```

На главной:

```
карточки всех контейнеров на этом хосте
зелёная лампа — работает, серая — остановлен
образ, порты, группа, короткий id
«Открыть ↗» и меню «⋯»
поиск по имени и образу
сводка «N из M работают», обновление раз в 10 секунд
```

Клик по карточке открывает страницу сервиса. Все действия — в меню «⋯»:
стоп/запуск, перезапуск, обновить, бэкап, ссылка, подробнее, удалить.

## 3. Группы

Раздел «Группы» в сайдбаре:

```
создать группу (имя до 64 символов)
переименовать
удалить (сервисы остаются без группы)
порядок групп стрелками ↑ ↓
```

На карточке есть список «Группа» — переносит сервис в выбранную группу.

## 4. Установка сервиса

Кнопка «Добавить сервис». Есть обычная форма и режим YAML.

Поля формы:

```
Имя          латиница, цифры, точка, дефис, подчёркивание
Образ        поиск по Docker Hub или ручной ввод
Порты        по одному в строке, например 8080:80/tcp
Тома         по одному в строке, например data:/data
Переменные   KEY=VALUE, каждая с новой строки
Перезапуск   unless-stopped, always, no, on-failure
```

Режим YAML (кнопка «YAML»):

```
вставить docker-compose с одним сервисом
поддерживаются image, ports, volumes, environment, restart
```

Поиск образа:

```
вводишь 2+ символа → подсказки через 300 мс
видно имя, звёзды, загрузки, official, описание
выбор подставляет имя и список тегов
тег можно выбрать: latest или конкретный
порты, тома и переменные подставляются из README образа, если поля пустые
```

После «Установить» панель скачивает образ, создаёт и запускает контейнер,
затем показывает его на главной. Ошибки (занятое имя, плохой порт, недоступный
образ) показываются в форме.

## 5. Действия

В меню «⋯» на карточке или на странице сервиса:

```
Старт        для остановленного
Стоп         с подтверждением
Перезапуск
Обновить
Бэкап
Ссылка
Удалить      с подтверждением; именованные тома сохраняются
```

## 6. Обновление

Кнопка «Обновить»:

```
скачивает образ того же тега
если образ не изменился — «уже последняя версия»
если изменился — пересоздаёт контейнер с теми же портами, томами,
  переменными и сетью, проверяет запуск
при сбое возвращает старый контейнер и запускает его
```

Важно: обновляется тот тег, который указан у контейнера. Для `nginx:alpine`
подтянется свежий образ, для `nginx:1.25-alpine` — тот же 1.25.

## 7. Ссылки

На карточке ссылка «Открыть ↗»:

```
по умолчанию: http://<хост панели>:<первый публичный порт>
кнопка «Ссылка» — задать свою, без ограничений по схеме
пустое значение возвращает автоматическую
```

## 8. Бэкапы

Вкладка «Бэкапы» на странице сервиса, кнопка «Создать копию»:

```
tar.gz через одноразовый alpine
файл в томе servatory-backups
проверка, что архив читается и не пустой
хранится 5 последних копий на сервис (настраивается)
```

Список копий: дата, размер, восстановление, удаление.

Что попадает в архив: только тома. Настройки контейнера не сохраняются.
Служебные монтирования (`/var/run/docker.sock`) пропускаются.

## 9. Восстановление

Вкладка «Бэкапы» на странице сервиса, кнопка «Восстановить» у копии:

```
1 подтверждение вводом имени сервиса
2 автоматическая safety-копия текущего состояния
3 остановка контейнера
4 очистка томов и распаковка архива
5 запуск и проверка состояния
```

Если контейнер не поднялся — панель пытается вернуть safety-копию и пишет
её имя. Восстанавливаются только тома, созданные через бэкапы панели.

## 10. Настройки

Файл `/data/config.toml` в контейнере (или `/var/lib/servatory/config.toml`
при нативной установке):

```toml
[server]
host = "0.0.0.0"
port = 8090

[auth]
login = "admin"
password = "admin"
role = "superadmin"
session_hours = 12

[ui]
language = "ru"
theme = "dark"

[docker]
socket = "/var/run/docker.sock"
timeout = 5

[backups]
dir = "/backups"
volume = "servatory-backups"
keep = 5

[logging]
level = "info"

[features]
demo = false
```

Переменные окружения перекрывают файл. После правки — перезапуск панели.
Данные (база групп, ссылок, сессий) — `/data/servatory.db`.

## 11. API

```
POST /api/v1/auth/login           вход, возвращает csrf
GET  /api/v1/auth/me              текущий пользователь
POST /api/v1/auth/logout          выход
GET  /api/v1/containers           список
POST /api/v1/containers           установка
DELETE /api/v1/containers/{id}    удаление
POST /api/v1/containers/{id}/actions/{start|stop|restart|update}
GET/POST /api/v1/containers/{name}/backups
DELETE /api/v1/containers/{name}/backups/{file}
POST /api/v1/containers/{name}/backups/{file}/restore
GET/POST/PATCH/DELETE /api/v1/groups
POST /api/v1/groups/reorder
POST /api/v1/containers/{name}/group
POST /api/v1/containers/{name}/link
GET  /api/v1/images/search?q=...
GET  /api/v1/images/tags?name=...
GET  /health, /ready
```

Все изменяющие запросы требуют заголовок `X-CSRF-Token`.

## 12. Журнал, проверки и логи

```
Настройки → Журнал      вход, выход, изменения, результат
карточка сервиса        строка «проверка: ок / ошибка»
страница сервиса        вкладка «Проверка»: адрес, интервал, результат
                        вкладка «Логи»: последние строки лога
```

Проверка работает в фоне: раз в 30 секунд панель обходит адреса,
у которых подошёл интервал.

## 13. Домены и TLS

«Настройки → Домены и TLS»:

```
домен      panel.example.com
почта      для Let's Encrypt
TLS        да
```

Панель поднимает Caddy на портах 80 и 443 и оставляет прямой вход
на 8090 как запасной. Для localhost и IP — внутренний сертификат,
для домена — обычный Let's Encrypt.
